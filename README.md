# 传奇足球经理 MVP

一个无需数据库和第三方 npm 依赖即可运行的多人网页足球经理游戏。界面为中文，支持 20 支球队、真人/AI 混合控制、蛇形选秀、自由阵型与职责、球队情报、DeepSeek AI 比赛模拟、逐场战报、关键事件、换人、球队与球员数据、球员评分、积分榜和射手榜。

## 启动

需要 Node.js 20 或更高版本。

```bash
export DEEPSEEK_API_KEY="你的 DeepSeek API Key"
npm start
```

浏览器打开 <http://localhost:3000>。房主创建联赛时可从 20 支球队中选择开局球队；其他玩家输入房间码后，会看到尚未被真人占用的球队并选择接管。同一台电脑可用无痕窗口模拟其他玩家。若从局域网其他设备访问，请使用运行电脑的局域网 IP（例如 `http://192.168.1.10:3000`）。

运行自动测试：

```bash
npm test
```

## DeepSeek AI 比赛引擎

新比赛由 `deepseek-v4-flash` 直接决定比分、进球者、浪费机会、关键传球、关键扑救、双方换人、所有出场球员评分、全场最佳、球队数据和完整中文战报。服务使用 DeepSeek 官方 OpenAI 兼容接口，不再使用 `deepseek-chat`、OpenAI 或本地泊松随机比分。

每次“AI 模拟下一轮”会把该轮 10 场拆成 5 个并行小批次，每批 2 场，并使用 V4 Flash 非思考模式避免大 JSON 响应超时；所有批次成功后才会一次性推进轮次。“AI 模拟全部”仍按轮次执行，完整 38 轮默认最多调用 190 个小批次。模型响应必须通过以下校验才会写入存档：

- 返回本轮全部 10 场且对阵与赛程完全一致。
- 进球事件数量会按最终比分校正，缺失的事件会使用本场首发自动补齐。
- 非进球关键事件会规范为 4–9 个，并确保包含浪费机会、关键传球和关键扑救。
- 每队会记录 1–3 次换人；AI 未给出合法换人时会从真实替补席自动补充一次。
- 双方 22 名首发与所有登场替补评分完整、无重复，评分介于 4.0–10.0。
- 控球率、射门、射正、绝佳机会、角球、犯规、传球成功率会被规范为合理范围，并生成个人出场时间、射门、传球、成功传球和红黄牌统计。

事件数量、换人、统计、评分说明和全场最佳等非关键格式问题会自动校正；对阵错误或 22 名首发评分缺失等数据完整性问题仍会拒绝整轮。拒绝时当前轮次不会推进，也不会写入部分比分、积分或射手数据。整季模拟若在中途失败，只保留此前已经完整完成的轮次。未配置 `DEEPSEEK_API_KEY` 时仍可进入房间和管理阵容，但不能模拟新比赛。旧存档中缺失的历史战报与统计仍会由本地迁移逻辑补齐。

## 默认规则

- 20 队单一联赛，每两队主客场各一次，共 38 轮、380 场。
- 房主与后来加入的真人玩家都可自行选择球队；已被真人占用的球队不可重复选择，其余球队继续由 AI 控制。
- 前半程每队拥有 9 或 10 个主场；旧版进行中的联赛会保留已赛轮次和结果，仅重新排序未赛轮次以恢复后续主客场平衡。
- 每队 18 人；默认采用蛇形选秀（也可设为普通顺序）。20 位 AI 经理拥有独立的姓名、战术风格和心态；创建房间时会按种子打乱经理与球队的组合，并从该风格适用的阵型池中加权选择。选秀会综合本队阵型配额、具体站位覆盖、位置熟练度、风格关键属性、总评、多位置能力及阵容冗余，再加入不超过约 3% 的种子差异，不再共用一张固定位置需求表。
- 选秀中心支持按位置筛选和按球员姓名即时搜索，两项条件可以组合使用，筛选状态会在当前选秀过程中保留；所有结果默认按总能力值从高到低排列，同分时按姓名稳定排序。
- 球员库共 360 名不重名真实球员，由传奇球星和近期现役球员组成，不再使用虚构占位球员；位置结构按完整阵容需求配平。
- 首发 11 人，共有 18 套预设：`4-3-3 DM`、`4-2-3-1`、`4-4-2`、`3-4-2-1`、`4-1-4-1`、`4-3-1-2`、`4-2-2-2`、`3-5-2`、`5-2-3`、`3-4-3`、`5-3-2`、`4-3-3 AM`、`4-3-3`、`4-1-2-1-2`、`4-2-4`、`3-4-1-2`、`3-2-4-1` 和 `5-4-1`。也可在球场编辑器中拖动十名外场球员和横向调整门将，创建每支球队独立保存的自由阵型。
- 自由阵型会根据落点自动识别中后卫、边后卫、后腰、中场、前腰、边锋和前锋，随后仍可为每个位置选择球员及有球/无球职责。
- 每个位置分别设置“有球职责”和“无球职责”，例如出球门将/积极出击、出球中卫/协防中卫、内收边后卫/压迫边卫、影子前锋/前场压迫等。
- 自动排阵会在整支 18 人名单中计算全局最优的 11 人位置组合，避免逐个位置贪心选人造成后续位置无人可用；AI 还会结合经理风格和球员属性自动选择更合适的有球/无球职责。
- 球员采用 1–20 属性制，包含 8 项技术、7 项精神、6 项身体和 5 项门将能力；总评仅作为选秀摘要，不再直接决定比赛结果。
- 球员详情包含身高、体重和 12 个具体位置的熟练度。主位置、副位置、相邻位置与陌生位置会形成逐级适配差异；手动安排到陌生位置会显著降低职责发挥、球队指标和 AI 比赛评分。
- 胜 3 分、平 1 分；同分依次比较净胜球、进球数。
- DeepSeek 会接收职责关键属性、球员身高体重、当前站位及对应位置熟练度、有球进攻与控制、无球防守与压迫、体能、门将能力、比赛心态及双方完整首发，用这些信息裁决比赛；AI 输出不保证相同输入得到完全相同的赛果。
- 每场比赛保存比分摘要、战术观察、全场最佳、所有出场球员评分与个人数据，以及进球、换人、浪费机会、关键传球和关键扑救时间线；个人数据包含出场时间、射门、传球、成功传球、红黄牌等，战报弹窗通过“比赛战报 / 数据统计”页签分别展示叙事与统计。
- 每次操作自动保存到 `data/games.json`，使用临时文件原子替换并保留 `games.json.bak` 备份。静态球员库不再重复写入每个房间。
- “球队情报”页面可以通过球场预览查看联赛中所有球队的完整名单、首发阵型、比赛心态和双阶段职责。
- 联赛大厅可以删除当前房间；必须再次输入完整房间码确认，删除前的存档会保留在 `games.json.bak`。

关键规则集中在 [`config.js`](./config.js)：可修改阵容人数、选秀模式（`snake` 或 `linear`）、阵型、双阶段职责和心态。创建房间时会保存规则快照，此后的全局配置修改不会改变进行中的联赛；`HOME_ADVANTAGE` 与 `RANDOMNESS` 仅为旧存档兼容字段，不再直接生成 AI 赛果。

近期现役球员名单主要参考 [UEFA 2025/26 欧冠注册阵容](https://www.uefa.com/uefachampionsleague/news/029d-1ea2da6b438f-0a4889826e05-1000--champions-league-squads-league-phase-selections-confirmed/)；位置、位置熟练度、身高体重和游戏属性用于本项目的简化比赛建模，并非官方数据库或实时测量数据。

战术设计参考 FM26 已公开的“有球/无球阵型与职责”理念，但采用了适合本网页游戏模拟器的原创简化规则，并非复制其数据库或比赛引擎。

## 项目结构

- `server.js`：HTTP 服务启动入口。
- `src/api.js`：API 路由、请求校验与静态资源服务。
- `src/storage.js`：精简存档、原子写入与备份恢复。
- `src/game.js`：房间创建、迁移和公开状态组装。
- `src/player-data.js` / `src/players.js`：真实球员库、属性与位置适配。
- `src/ai-manager.js`：AI 经理档案、阵型人数规划、战术偏好和选秀评分。
- `src/schedule.js`、`src/draft.js`、`src/lineup.js`、`src/match.js`：赛程、选秀、阵容、AI 结果校验和比赛统计模块。
- `src/match-ai.js`：DeepSeek V4 Flash 请求、比赛上下文和 JSON 输出约束。
- `src/report.js`：旧存档基础战报迁移。
- `public/`：中文单页界面。
- `test/`：核心规则、存档和 API 自动测试。

## MVP 限制与后续部署

本版通过房间码协作，暂不包含账户密码、权限校验和实时推送；其他玩家操作后刷新页面可取得最新状态。单进程部署可直接使用当前 JSON 存档。正式公网部署时，建议把存档层替换为 SQLite/PostgreSQL，并加入登录鉴权与 WebSocket 实时同步。
